## 2. 中间件准备

### 2.1 检查 MySQL 与 Redis 是否在跑

```powershell
# MySQL：能返回版本即正常
mysql -uroot -proot -e "SELECT VERSION();"

# Redis：返回 PONG 才叫正常
redis-cli -p 6379 ping
```

### 2.2 Redis 启动（两种方式，任选其一）

```powershell
# 方式一：Docker（推荐，版本可控）
docker run -d --name trade-redis -p 6379:6379 redis:7-alpine

# 方式二：本机已安装的 Redis 服务
redis-server                      # 前台启动，保持窗口不关
# 或以服务方式
net start Redis
```

> 仓库内 `_tools\redis\redis-server-2.8.19.exe` 是**兜底用的便携版**，本机实测启动失败（`QForkMasterInit: CreateDirectoryA failed`），仅在 6379 实在起不来时尝试；正常情况用 Docker 或系统已装 Redis。版本低于 5.0 时 Lua 脚本里的 `SETNX/EXPIRE/HMSET` 语义与过期策略差异较大，不建议用 2.x 演示（本项目限流脚本的时间戳由 Java 传入，不依赖 `redis.call('TIME')`，版本敏感点主要在脚本缓存与过期行为）。

### 2.3 RabbitMQ 不需要装

`application.yml` 里 `app.mq.enabled: ${MQ_ENABLED:false}`：

- `false`（默认）：`RabbitMQConfig` 与 `OrderCloseConsumer` 都带 `@ConditionalOnProperty`，**不声明队列、不建连接、不启监听器**，应用能正常启动。
- `true`（可选演示）：需要本机 5672 可达，才会建 `order.delay.exchange / order.delay.queue / order.dlx / order.close.queue` 并启用消费者。

关单不依赖 MQ：`OrderCloseTask` 每分钟扫描 `status=0 AND create_time < now-30min` 的订单（批量 100）调用同一个幂等 `closeOrder`。

## 3. 建库与导入数据

### 3.1 建库

```powershell
mysql -uroot -proot -e "CREATE DATABASE IF NOT EXISTS trade_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
```

### 3.2 建表 + 种子数据（顺序不能反）

```powershell
cd S:\ai\deepseek\简历\project-a-trade

# 12 张表 + 索引 + 注释
mysql -uroot -proot trade_db < sql\schema.sql

# 种子数据：账号、商品/SKU/库存、秒杀活动、若干订单
mysql -uroot -proot trade_db < sql\data.sql
```

> Windows PowerShell 的 `<` 重定向在部分版本不可用，若报“不支持重定向”，改用：
> `Get-Content sql\schema.sql -Raw | mysql -uroot -proot trade_db`
> （同理导 `data.sql`）。**注意 `-Raw` 不能省**，否则中文注释按行拆分会乱码。

### 3.3 校验导入结果

```powershell
mysql -uroot -proot trade_db -e "SHOW TABLES;"
mysql -uroot -proot trade_db -e "SELECT COUNT(*) AS users FROM t_user; SELECT COUNT(*) AS products FROM t_product; SELECT COUNT(*) AS activities FROM t_seckill_activity;"
mysql -uroot -proot trade_db -e "SELECT username,status FROM t_user;"
```

预期：12 张表（`t_user`、`t_product`、`t_sku`、`t_stock`、`t_seckill_activity`、`t_seckill_sku`、`t_order`、`t_order_item`、`t_payment_record`、`t_refund`、`t_mq_consume_log`、`t_stock_log`），`t_user` 里能看到 `buyer1` 与 `admin`，密码字段是 BCrypt 摘要（以 `$2a$` 开头，不是明文）。

### 3.4 时区（只在这一步出错时看）

连接串已写死 `serverTimezone=Asia/Shanghai`，MySQL 会话时区与 JVM 时区不一致时**不会**导致秒杀时间窗错乱。若 `SELECT NOW()` 与本机时间差 8 小时，先执行：

```sql
SET GLOBAL time_zone = '+08:00';   -- 需 SUPER 权限，重启 MySQL 后失效
```

### 7.1 页面路径（8 步走完一条交易闭环）

| # | 操作 | 页面 | 预期 |
|---|---|---|---|
| 1 | `buyer1` 登录 | `/login` | 跳 `/products`，右上角显示昵称 |
| 2 | 看商品列表 / 详情 | `/products`、`/products/:id` | 分页、SKU 与库存正常展示 |
| 3 | 进秒杀专区，看活动与实时库存 | `/seckill` | 活动倒计时；SKU 库存来自 Redis |
| 4 | 点“立即抢购” | `/seckill` | 返回订单号，跳订单列表；库存 -1 |
| 5 | 我的订单 / 详情 | `/orders`、`/orders/:orderNo` | 状态 `0 待支付` |
| 6 | 点“模拟支付” | 订单详情 | 状态变 `1 已支付`，`t_payment_record` 多一条 |
| 7 | 点“申请退款”填理由 | 订单详情 | 状态变 `5 退款中`，生成退款单号 |
| 8 | 换 `admin` 登录 → 退款审核 → 通过 | `/admin/refunds` | 状态变 `6 已退款`，库存回补 |

运营侧另需验证：`/admin/products` 新增商品（含 SKU）、改价、调库存；`/admin/activities` 创建活动并点“预热”；`/admin/dashboard` 今日销售额/订单数/待审退款/库存预警、销售趋势。

### 7.2 curl 全链路（不打开浏览器也能验收）

```powershell
$base = "http://localhost:8080/api"

# ① 登录（买家）
$login = curl -s -X POST "$base/auth/login" -H "Content-Type: application/json" `
  -d '{"username":"buyer1","password":"123456"}' | ConvertFrom-Json
$token = $login.data.token
$h = @{ Authorization = "Bearer $token" }

# ② 秒杀活动列表 → 取活动 id
$acts = curl -s "$base/seckill/activities" | ConvertFrom-Json
$activityId = $acts.data[0].id

# ③ 活动详情 → 两个 id 别搞混：
#    skuId        = t_sku.id（下单路径里用这个）
#    seckillSkuId = t_seckill_sku.id（Redis 库存 key 里用这个）
$detail = curl -s "$base/seckill/activities/$activityId" | ConvertFrom-Json
$skuId = $detail.data.skus[0].skuId
$seckillSkuId = $detail.data.skus[0].seckillSkuId

# ④ 秒杀下单（返回订单号）
$order = curl -s -X POST "$base/seckill/$activityId/skus/$skuId" -Headers $h | ConvertFrom-Json
$orderNo = $order.data.orderNo

# ⑤ 我的订单
curl -s "$base/orders?page=1&size=10" -Headers $h

# ⑥ 模拟支付（内部走回调逻辑：验签→加锁→幂等→状态机 CAS）
curl -s -X POST "$base/pay/mock/$orderNo" -Headers $h

# ⑦ 申请退款
curl -s -X POST "$base/refunds" -Headers $h -H "Content-Type: application/json" `
  -d "{`"orderNo`":`"$orderNo`",`"reason`":`"尺码不合适`"}"

# ⑧ 运营审核退款
$admin = (curl -s -X POST "$base/auth/login" -H "Content-Type: application/json" `
  -d '{"username":"admin","password":"123456"}' | ConvertFrom-Json).data.token
$ah = @{ Authorization = "Bearer $admin" }
$refunds = curl -s "$base/admin/refunds?page=1&size=10&status=0" -Headers $ah | ConvertFrom-Json
$refundId = $refunds.data.records[0].id
curl -s -X POST "$base/admin/refunds/$refundId/audit" -Headers $ah -H "Content-Type: application/json" `
  -d '{"approved":true,"remark":"同意退款"}'
```

## 8. 常见错误排查（现象 / 原因 / 修法）

### 8.1 端口被占用

- **现象**：启动报 `Web server failed to start. Port 8080 was already in use`；或前端报 `EADDRINUSE: address already in use 5173`。
- **原因**：上一个 Java/Vite 进程没退（IDE 里 Stop 不彻底、`java -jar` 窗口被关但进程残留）。
- **修法**：
  ```powershell
  netstat -ano | findstr :8080        # 拿到 PID
  taskkill /PID <PID> /F
  # 前端同理换 5173；或临时换端口：java -jar target\trade-1.0.0.jar --server.port=8082
  #                          Vite：npm run dev -- --port 5175（同时要改 vite.config.js 代理目标）
  ```

### 8.2 MySQL 连不上 / 认证失败

- **现象**：启动报 `Communications link failure`、`Access denied for user 'root'@'localhost'`、或 `Public Key Retrieval is not allowed`。
- **原因**：MySQL 没起、密码不是 `root`、或 MySQL 8 的 `caching_sha2_password` 插件要求公钥。
- **修法**：
  1. `mysql -uroot -proot -e "select 1"` 先确认能连；连不上先起 MySQL（phpstudy/服务里启动）。
  2. 密码不是 `root`：`$env:DB_PASSWORD="你的密码"` 后重启 jar，**不要改 `application.yml` 里的默认值**。
  3. 公钥问题：连接串已带 `allowPublicKeyRetrieval=true`，若仍报错说明 jar 是旧包，重新 `mvn clean package`。

### 8.3 Redis 没启动 → 全站 503 / 登录失败

- **现象**：登录接口返回 `{"code":503,"msg":"认证服务暂不可用，请稍后重试"}`；或所有已登录接口突然 401；日志里 `RedisConnectionFailureException`。
- **原因**：JWT 白名单（`trade:auth:whitelist:{jti}`）强依赖 Redis，这是**有意为之的 fail-closed**：宁可拒绝也不放行绕过登录态校验。Redis 挂了，白名单查不到，等于所有 token 失效。
- **修法**：把 Redis 起起来（§2.2），`redis-cli ping` 得 `PONG` 后**用户重新登录一次**（旧 token 的 jti 不在白名单里，只能重新签）。
  ```powershell
  redis-cli -p 6379 monitor     # 另开窗口，能实时看到 GET trade:auth:whitelist:* 就说明链路通了
  ```

### 8.4 RabbitMQ 未装却把 `MQ_ENABLED` 打开了

- **现象**：启动 30 秒后报 `AmqpConnectException: Connection refused: localhost/127.0.0.1:5672`，随后应用退出或一直重连刷日志。
- **原因**：`app.mq.enabled=true` 时 `RabbitMQConfig` 会去声明 exchange/queue，`OrderCloseConsumer` 会建监听容器，连不上 broker 直接失败。
- **修法**：保持 `enabled: false`（默认）。确认命令：
  ```powershell
  echo $env:MQ_ENABLED        # 应为空或 false
  ```
  确需演示 MQ，先装 RabbitMQ 并确认 `Test-NetConnection localhost -Port 5672` 为 True，再设 `MQ_ENABLED=true` 重启。

### 8.5 跨域（CORS）报错

- **现象**：浏览器控制台 `has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header`，接口 200 但前端拿不到数据。
- **原因**：前端没走 Vite 代理（例如直接用 `http://localhost:8080/api/...` 调接口，或在 5173 之外另起了静态服务器），跨域请求被浏览器拦。
- **修法**：前端一律用相对路径 `/api/...`（`utils/request.js` 里 `baseURL: '/api'`），由 `vite.config.js` 代理转发；不要在前端写后端绝对地址。生产环境用 Nginx 把 `/api` 反代到 8080，见 §8.6。

### 8.6 前端刷新 404 / 生产环境接口 404

- **现象**：开发环境 `/orders/xxx` 刷新正常，`npm run build` 部署后刷新任意子路由变 404；或部署后接口全是 404。
- **原因**：路由是 `createWebHistory()`（history 模式），Nginx 没配 `try_files` 回落到 `index.html`；接口 404 是 Nginx 没配 `/api` 反向代理。
- **修法**（Nginx 最小配置）：
  ```nginx
  server {
    listen 80;
    root /usr/share/nginx/html/trade;      # dist 内容
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; }
  }
  ```

### 8.7 JWT 过期 / 登出后仍被拒

- **现象**：接口返回 `401`「未登录或登录已失效」，前端被踢回登录页；或刚点登出，用旧 token 再请求立刻 401。
- **原因**：token TTL 默认 120 分钟（`JWT_EXPIRE_MINUTES`）；登出会删白名单 key，旧 token 立即失效（这是特性，不是 bug）。
- **修法**：重新登录；调试期可临时把 `JWT_EXPIRE_MINUTES` 调大。用 `jwt.io` 粘贴 token 时**注意这是 dev 密钥签的，只在本机调试**。

### 8.8 秒杀提示“活动未预热”或“库存已抢完”

- **现象**：点抢购返回 409「手慢了，秒杀库存已抢完」；但数据库 `t_seckill_sku.stock` 还有值。
- **原因**：秒杀库存以 Redis `trade:seckill:stock:{seckillSkuId}` 为准。运营建完活动**应该点一次“预热”**把 DB 库存写进 Redis；漏点也不会卡死——下单链路发现 key 不存在（Lua 返回 `-1`）会用 `SETNX` 从 DB 自动回填一次再重试，但如果 DB 秒杀库存本身是 0，就仍会返回“已抢完”。
- **修法**：管理员账号登录 → `/admin/activities` → 对应活动点“预热”（`POST /api/admin/seckill/activities/{id}/preheat`），或确认活动时间窗内、DB 里 `t_seckill_sku.stock > 0`。然后核对：
  ```powershell
  redis-cli -p 6379 get "trade:seckill:stock:<seckillSkuId>"
  ```
  注意 key 用的是 `seckillSkuId`（活动详情里 `skus[].seckillSkuId`），不是下单路径里的 `skuId`。

### 8.9 秒杀下单报 409 但订单没生成（Redis 已扣）

- **现象**：接口 409/500，`t_order` 没新记录，但 `trade:seckill:stock:*` 少了 1；或该用户一直提示“您已抢到过该商品”。
- **原因**：Lua 预扣成功、同步 DB 事务失败（库存不足、唯一索引 `(user_id, seckill_sku_id)` 撞了重复下单、连接超时），`SeckillServiceImpl` 的补偿逻辑要把 Redis 库存 `INCR` 回去并删除该用户的幂等 key `trade:seckill:user:{seckillSkuId}:{userId}`；若补偿本身失败（Redis 抖动），就会短暂“少卖 + 用户被锁”。
- **修法**：正常路径由补偿逻辑、`OrderCloseTask`（关单回滚）与对账任务收敛；手工修：
  ```powershell
  redis-cli -p 6379 incr "trade:seckill:stock:<seckillSkuId>"
  redis-cli -p 6379 del  "trade:seckill:user:<seckillSkuId>:<userId>"
  ```
  删幂等 key 这一步不能省，否则该用户 24 小时内都抢不到（一人一单标记还在）。

### 8.10 `mvn` 卡住 / 找不到依赖

- **现象**：`mvn package` 长时间停在 `Downloading from central`，或报 `Could not resolve dependencies`。
- **原因**：首次构建需要从 Maven 中央仓库下载 Boot/MP/Security/Redis 等依赖，网络慢；或本地 `~/.m2` 缺包。
- **修法**：在 `~/.m2/settings.xml` 配阿里云镜像后重试；网络恢复后再联网打包。不要依赖固定的本机仓库路径（`.mvn/maven.config` 已不绑定路径）。

### 8.11 前端 `npm install` 失败 / 构建报 “is not exported by vue”

- **现象**：`npm run build` 报 `"toValue" is not exported by node_modules/vue/...`、`"hasInjectionContext" is not exported by vue`。
- **原因**：`vite.config.js` 的 `vue → src/shims/vue-compat.js` 别名被改动（比如把 `resolve.alias` 改成字符串数组时把 `find: /^vue$/` 写成 `'vue'`），或把 `vue` 版本升到 3.3+ 但 Element Plus 版本没同步。
- **修法**：还原别名配置（见 `vite.config.js` 顶部注释），别升级 `vue`；`node_modules` 删掉重装一次。

### 8.12 密码正确却提示“用户名或密码错误”

- **现象**：`buyer1 / 123456` 登录失败，返回 400「用户名或密码错误」。
- **原因**：`data.sql` 没导或导入时中文乱码导致 `password` 字段截断；或手工改过 `t_user.password`（存成了明文）。
- **修法**：重新导 `data.sql`，并确认 `SELECT username, LEFT(password,4) FROM t_user;` 是以 `$2a$` 开头。
