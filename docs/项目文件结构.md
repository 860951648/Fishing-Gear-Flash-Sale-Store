## 2. 后端（`backend/src/main`）

### 2.1 启动与全局约定

| 文件 | 一句话职责 |
|---|---|
| `TradeApplication.java` | 启动类：`@SpringBootApplication` + `@MapperScan` + `@EnableScheduling`（定时任务开关）+ `@EnableTransactionManagement`，端口 8080 |
| `common/Result.java`、`ResultCode.java`、`PageResult.java`、`BusinessException.java` | 统一返回 `{code,msg,data}`、业务码枚举（200/400/401/403/404/409/429/500/503）、分页 `{total,pages,current,size,records}`、带业务码的运行时异常（样板类合并） |
| `common/GlobalExceptionHandler.java` | `@RestControllerAdvice`：业务异常 / 参数校验（BindException、MethodArgumentNotValid）/ 认证鉴权 / `RedisConnectionFailureException`(503) / `DuplicateKeyException`(409) / 兜底 500，全返回 `Result` JSON |
| `common/Constants.java` | 订单 7 状态、退款 3 状态、库存日志类型、超时 30 分钟、批量 100、缓存时长（商品 5 分钟、空值 60 秒）、秒杀幂等 24 小时、支付锁 10 秒、限流 20/10、权限缓存 5 分钟——集中一处便于审计 |

### 2.2 安全与认证（Spring Security 7 + JWT + 白名单）

| 文件 | 一句话职责 |
|---|---|
| `config/SecurityConfig.java` | 过滤器链：关 CSRF、开 CORS、`STATELESS`、放行 `OPTIONS`/注册/登录/支付回调/商品与活动 GET；`JwtAuthenticationFilter` 插在 `UsernamePasswordAuthenticationFilter` 之前；挂 401/403 JSON 处理器；`@EnableMethodSecurity` 打开 `@PreAuthorize`；定义 `BCryptPasswordEncoder` |
| `security/JwtAuthenticationFilter.java` | 每请求：`Authorization: Bearer` → 验签 → 查白名单 `trade:auth:whitelist:{jti}` → 比对 `trade:auth:ver:{userId}` → 重建 `LoginUser.authorities` → 写 `SecurityContext`；Redis 故障返回 503 而不是 401 |
| `security/JwtUtils.java` | JWT 签发/解析（HS256，`app.jwt.secret` ≥32 字节、`expire-minutes` 120），claims 只放 `sub=userId`、`jti`、`ver` |
| `security/LoginUser.java` | 登录人上下文：`userId/username/nickname/jti/tokenVersion/authorities`，实现 `hasAuthority` 供 service 判断 |
| `security/RestAuthenticationEntryPoint.java`、`RestAccessDeniedHandler.java`、`JsonAuthWriter.java` | 401（无身份）/403（无权限）统一出口，`JsonAuthWriter` 把 `Result` 写成 `application/json`，避免 Spring 默认 HTML 页 |

### 2.4 业务服务（10 组接口 + 实现，共 20 个文件）

| 服务 | 一句话职责 |
|---|---|
| `AuthService` / `AuthServiceImpl` | 注册（BCrypt）、登录（查用户 → 校验 → 取 token 版本 → 签 JWT → 写白名单 → 返回权限码）、登出（删白名单，token 立即失效）、`me` |
| `PermissionService` / `PermissionServiceImpl` | 权限码推导：`admin` → 5 个管理码，其余账号只登录；`trade:perm:{userId}` 缓存 5 分钟；改权限时删缓存 |
| `ProductService` / `ProductServiceImpl` | 商品列表（DB 分页）、详情（Hash 缓存 `trade:product:{id}`：`data`+`expireAt`，逻辑过期 + `SETNX` 锁重建 + 空值缓存 60 秒防穿透） |
| `SeckillService` / `SeckillServiceImpl` | 活动列表/详情（实时库存取 Redis）、秒杀下单：令牌桶限流 → Lua 原子预扣（`-1/0/2/1`）→ 同步 DB 事务 → 失败补偿 `INCR`+删幂等键 → 事务后投递延迟关单消息 |
| `OrderService` / `OrderServiceImpl` | 创建秒杀订单（事务：两处条件扣减 + 订单/明细/库存流水）、订单列表与详情、取消、`markPaid`、`closeOrder` 幂等关单（CAS 到 4 后回滚 DB/Redis 库存并写 `t_stock_log`） |
| `PaymentService` / `PaymentServiceImpl` | `mockPay`（本地模拟网关：生成渠道号 + HMAC 签名后走同一入账）与 `callback`（验签 + 时间戳容差）→ 锁 `trade:lock:pay:{orderNo}` → 渠道号幂等 → 状态机 CAS `0→1` → 写 `t_payment_record` → Lua 解锁 |
| `RefundService` / `RefundServiceImpl` | 申请退款（订单 1/2/3 → 5，写 `t_refund`）、我的退款分页、运营审核（通过 5→6 回滚库存；驳回 5→1 恢复已支付） |
| `AdminProductService` / `AdminProductServiceImpl` | 商品 CRUD（事务内商品+SKU+库存三者一起成功/失败）、调整可用库存、逻辑删除；写后删商品详情缓存 |
| `AdminSeckillService` / `AdminSeckillServiceImpl` | 活动创建（时间窗与 SKU 校验、唯一 `(activity_id, sku_id)`）、运营列表、预热（DB 秒杀库存覆盖写 `trade:seckill:stock:{seckillSkuId}`） |
| `StatsService` / `StatsServiceImpl` | 运营看板：今日销售额/订单数/待审退款/库存预警 + 近 N 天趋势（聚合交 `StatsMapper.xml`，金额两位 HALF_UP、趋势按天补零） |

### 2.6 消息与定时任务

| 文件 | 一句话职责 |
|---|---|
| `mq/producer/OrderDelayProducer.java` | 发送延迟关单消息（只带 `orderNo + messageId + sendTime`）；`app.mq.enabled=false` 时只打日志返回，发送失败也只记 error——下单主流程不因 MQ 失败而失败 |
| `mq/consumer/OrderCloseConsumer.java` | `@ConditionalOnProperty` 注册的关单消费者：先插 `t_mq_consume_log(message_id)` 幂等，再调 `OrderService#closeOrder`；手动 ACK，异常 `nack(requeue=false)` 进死信 |

| `task/OrderCloseTask.java` | `@Scheduled(fixedDelay=60s)` 扫 `status=0 且 create_time < now-30min`（`LIMIT 100`）逐单幂等关单——MQ 关闭/抖动时的第二条路径 |
| `task/StockReconcileTask.java` | 每天 03:30 对账：以 DB 秒杀库存为准覆盖 Redis 并打印差异（只对进行中的活动，避免给已结束活动重新灌库存） |
